Rasengan UI

Component Library Active Open source

A headless, accessible React component library with 60+ primitives, token-based theming and first-class TypeScript support. Built for teams that want the design system work already done — without giving up control of the CSS.

Homepagerasengan.dev RepositoryGitHub DocumentationDocs site Issues37 open

Overview

Rasengan UI started as the internal component kit behind three production apps. Every primitive was extracted from a real feature — the dialog came from a billing flow, the data table from an analytics dashboard, the command palette from a keyboard-first admin tool. Nothing exists speculatively.

The library ships headless behaviour with unstyled defaults: state machines, focus management and ARIA wiring are handled for you, while the visual layer is plain CSS driven by design tokens. Adopt it wholesale or copy a single component — there is no runtime CSS-in-JS, no wrapper divs, and no styling opinions you cannot override in one place.

  • 60+ accessible primitives — dialogs, popovers, menus, tables, forms and more, tested against WCAG 2.2 AA.
  • Token-based theming — one CSS file maps colour, radius, spacing and motion tokens; dark mode is a single attribute.
  • First-class types — every prop typed, generics for data tables, and no any in the public API.
  • Tiny bundles — tree-shakeable ESM, 0 dependencies, 12.4 kB gzipped for the core.
  • SSR & RSC ready — works with Next.js, Remix and plain Vite, server rendering included.

Getting started

Install it, import a token file, and render your first component in under a minute.

bash 
npm install @rasengan/ui @rasengan/tokens
# or
pnpm add @rasengan/ui @rasengan/tokens
TSX 
import { Dialog, Button, TextInput } from "@rasengan/ui";
import "@rasengan/tokens/base.css";

export function InviteMember() {
  return (
    <Dialog>
      <Dialog.Trigger asChild>
        <Button>Invite member</Button>
      </Dialog.Trigger>
      <Dialog.Content title="Invite member">
        <TextInput label="Email" type="email" required />
        <Dialog.Footer>
          <Button variant="ghost">Cancel</Button>
          <Button>Send invite</Button>
        </Dialog.Footer>
      </Dialog.Content>
    </Dialog>
  );
}
Good to know

Every component accepts a className and forwards refs. If you use Tailwind, Radix-style slot props and design tokens coexist without conflicts.
